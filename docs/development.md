# Docker development and the first TDD cycles

## Current status

Part of M0 is implemented: a TypeScript/pnpm workspace, container tooling, watch mode, `SignalStore`, `CommandBook`, `VirtualLed`, and `PgCommandJournal`. RED → GREEN cycles have been observed; full-suite and TypeScript results are recorded in the [TDD log](tdd-log.md).

`SignalStore` keeps values in memory, including quality, monotonic freshness, boot sessions, duplicates, ordering, exact int64/uint64, and disconnection. A trusted gateway calls `beginSession` after device verification; the class does not authenticate MQTT hello messages. Missing data remains `null`; disconnection preserves the last value with `Disconnected` quality.

`CommandBook` is a synchronous lifecycle model for boolean commands in the LED milestone. It checks output ownership, quality, interlocks, revision, boot session, and TTL; deduplicates requests; and separates dispatch, ACK, and result evidence. A trusted application supplies context, not the browser. `CommandBook` itself is in-memory and must not be connected to physical outputs as a standalone command service.

`PgCommandJournal` adds PostgreSQL persistence: transactional commands/events/outbox, concurrent deduplication, one-time intent issuance, and expiration recovery. It restores snapshots through the same `CommandBook` model. One unfinished command is allowed per output; Unknown blocks new requests until future explicit reconciliation. See the [journal contract](command-journal.md) for details, time assumptions, and remaining limitations. MQTT delivery and runtime scheduling are not connected yet.

`VirtualLed` models one output with OFF as the LED-specific safe state and a maximum 3000 ms lease. All model participants share one monotonic virtual clock; its `expiresAt` cannot be transferred directly to a network contract between physical devices with independent clocks. The watchdog calculates state when the model is accessed rather than running a hardware timer. The model neither executes ESP32 firmware nor connects to MQTT yet. Its completed-command cache is limited to 10,000 entries per boot; once full, new entries are rejected until model reboot.

## First run

Requirements: Linux x86-64, Docker Engine accessible to the current user, and Docker Compose. Initial setup needs registry access or pre-imported images and packages. This development environment is not yet the complete offline product distribution.

From the `open-apcs` directory:

```bash
# Once: build the Node/pnpm tooling image. Sources are not copied into it.
make image

# Install locked dependencies into a named Docker volume.
make install

# Repository language check, TypeScript, and all existing unit/integration tests.
make test

# Watch source and test changes continuously.
make watch
```

`pnpm-lock.yaml` was generated by a real Docker installation and is committed with the sources. `make install` uses `--frozen-lockfile`; direct and transitive versions are pinned. `make bootstrap` is only for creating a new workspace without a lockfile; it is unnecessary in this repository. Node, PostgreSQL, and Mosquitto are pinned by tag and digest. A new environment still requires registries or prepared caches/images until the offline bundle is delivered.

## Development without image rebuilds

The `.:/workspace` bind mount makes file changes immediately available inside containers. `node_modules` and the pnpm store use named volumes, keeping container dependencies separate from host dependencies. Vitest watch reruns affected tests. Process watch and Vite HMR will be added with the first tested Node/frontend applications.

`make watch` runs in the foreground; `make watch-bg` starts the same service in the background. Follow logs with `docker compose -f compose.test.yml logs -f unit-watch`. `make watch-integration` starts the PostgreSQL/MQTT watcher; use `docker compose -f compose.test.yml up -d integration-watch` for background mode. Hot reload was verified through RED → GREEN source edits. SQL migrations also trigger reruns.

| Changed item | Action |
|---|---|
| Source or test | None: the watcher detects it |
| `package.json` or workspace dependency | Update dependencies in Docker, save the lockfile, restart the watcher if needed |
| Lockfile only after pull | `make install` |
| Node/pnpm or Dockerfile | `make image`, then recreate the container |
| Compose service configuration | Recreate the affected service; no image build if the Dockerfile is unchanged |

To run commands in an existing container:

```bash
docker compose -f compose.test.yml up -d toolbox
docker compose -f compose.test.yml exec toolbox pnpm test:unit
docker compose -f compose.test.yml exec toolbox pnpm typecheck
```

For example, update a dependency with:

```bash
docker compose -f compose.test.yml run --rm deps pnpm add -Dw package-name@exact-version
```

Installation is an explicit operation, not part of every hot reload. Library changes do not require rebuilding the tooling image. Pinned base-image digests do not replace the future offline bundle of packages and toolchains.

## All existing tests

```bash
make test
```

This runs the repository language guard, TypeScript checks, then every unit/integration test. PostgreSQL and MQTT run as real containers with health checks, not mocks. A failed check or test returns a nonzero exit code. Beyond infrastructure smoke tests, the command journal has atomicity, concurrency, recovery, and fault-injection tests. These do not replace the future API, gateway, and firmware tests.

The GitHub Actions workflow `.github/workflows/test.yml` builds the image, performs a frozen installation, runs `make test`, and stops the test services. All application checks run in containers. Remote Actions execution must be verified separately from local test results. The [official checkout action](https://github.com/actions/checkout) is pinned to a commit SHA with credential persistence disabled.

For individual checks:

```bash
make unit
make integration
make typecheck
docker compose -f compose.test.yml run --rm --no-deps unit pnpm check:language
docker compose -f compose.test.yml run --rm integration-watch
```

The `open-apcs-test` project is separate from `open-apcs-dev`. It has separate volumes, an internal network, temporary PostgreSQL, and MQTT without published host ports. Fixture passwords and anonymous MQTT belong only to this isolated environment. Production requires local authentication and broker ACLs as specified.

`compose.yml` provides a separate development toolbox/watcher. Install its dependencies separately with `docker compose run --rm deps`; the lockfile is shared but dependency volumes are separate. Do not run concurrent dependency installers within the same Compose project.

```bash
# Stop only the test project, preserving dependency caches.
make stop
```

## Phase commits and language

Before each completed phase is committed, update the specifications and status in English, run `make test`, review the changes, and push the phase commit to the configured project repository. The language guard scans authored text for Cyrillic and skips dependencies, generated outputs, Git internals, and private environment files. It is a supplementary guard: contributors must still write clear English. Unicode remains supported in user-defined data.
